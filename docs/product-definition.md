# 产品定义：DSH 模型运行守护

## 一句话定位

为使用 DeepSeek Harness 的个人开发者，提供一个可分发的“模型运行守护”插件：在对话接近容量、模型长时间无有效输出、工具调用异常或第三方网关协议不兼容时，自动诊断、安全恢复并明确告知用户发生了什么。

## 核心场景

1. 切换到 ChatGPT / OpenCode Go / 千问等模型后，回复长时间停在思考中，用户无法判断是正常工作、已超限还是卡死。
2. 历史对话很长但未到默认 80% 压缩阈值，缺少提前整理，导致后续请求变慢或失败。
3. 第三方网关（如 OpenCode Go DeepSeek）在“思考＋工具调用续接”时协议不稳定，造成思考被当正文、任务中断或静默断流。
4. 模型进入重复工具调用、空回复或仅思考回复的“死亡循环”，没有硬上限和可见恢复路径。
5. 用户希望在不泄露对话内容、密钥或模型私有思考的前提下，导出可复现的诊断证据。

## MVP 范围（第一版做）

### In

1. **自动上下文压缩插件**  
   - 调研 KUN、ChatGPT 等主流 Agent 的自动压缩触发阈值与实现原理；  
   - 为 DSH 实现一个独立的自动压缩插件，支持按路由配置触发阈值、保留最近历史、摘要失败安全降级；  
   - 不修改 DSH 核心，不与现有 `dsh-compaction-basic` 冲突。

2. **DSH 已知问题调研清单**  
   - 梳理 DeepSeek Harness 自发布以来的公开问题、社区反馈与本机验证的兼容性问题；  
   - 以 Markdown 形式生成一份结构化清单，保存到用户的下载目录；  
   - 清单仅含问题描述、影响范围、复现条件、当前状态与规避方式，不含对话正文或密钥。

### Out（第一版不做）

- 运行状态面板、去敏诊断记录、有限安全恢复、已知兼容问题库 UI、DSH 核心修复清单生成器等其余功能；
- 强制终止卡死流/工具、全局硬上限、持久化状态机、原子恢复、精确成本账单、跨进程断路器等核心级改动；
- 修改或重写上游模型输出内容。

## 成功指标

- 自动压缩插件可在 DSH 中独立加载，不与现有 `dsh-compaction-basic` 冲突；
- 插件支持至少 DeepSeek 官方、ChatGPT/Codex、OpenCode Go DeepSeek、千问四类路由的阈值配置；
- 摘要失败时保留原历史并明确提示，不静默丢上下文；
- DSH 已知问题清单以 Markdown 保存到用户下载目录，内容结构化、零敏感数据；
- 清单至少覆盖 pi #7702 / PR #7701、OpenCode #25000 及本机验证的 OpenCode Go DeepSeek reasoning 回放风险。
